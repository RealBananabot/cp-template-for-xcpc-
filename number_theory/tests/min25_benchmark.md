## 计算组织方式

当前 calc(x,i) 从一条质因数分解路径出发，枚举下一个质数及其指数。路径的乘积 d 不同，即使随后得到相同的 (floor(n/d),i)，也会再次计算；没有状态合并。例如 n=1000 时，路径乘积 d=120 与 d=125 的最大质因子都为 5，均会调用 calc(8,3)，这里 3 表示已经排除 2、3、5。

反向 DP 从质数贡献开始，按质数 p 递减，将最小质因子恰为 p 的合数贡献逐层加回。每一阶段只为不同整除商 x 保留一个状态，并按 x 递减原地更新，从而在读取 x/p^e 时仍使用上一阶段的值。

具体令 A(x) 为质数上的目标函数和，H_p(x) 为“全部质数，以及最小质因子大于 p 的合数”的目标函数和；反向恢复 p 时增加：

```text
sum_{e>=1, p^(e+1)<=x} [F(p^e)*(H_p(floor(x/p^e))-A(p)) + F(p^(e+1))]
```

最终得到所有 >=2 的整数的贡献，再加入 F(1)。代码与原理参考 [AtCoder 官方说明](https://atcoder.jp/contests/abc370/editorial/10906) 的 Lucy DP、black algorithm 和 Min_25 三节，以及 [直接 DFS 与记忆化实现的分析](https://baihacker.github.io/main/2020/The_prefix-sum_of_multiplicative_function_the_black_algorithm.html)。这里比较的是普通反向 DP，没有改成带树状数组的更复杂版本。

## 当前递归实现的严格复杂度

以 Pmax(d) 表示 d 的最大质因子，令

```text
R(n) = #{d>=2 : d*Pmax(d)<=n}。
```

每次 calc 调用对应一条按质数递增选取质数幂的路径，乘积 d 的分解唯一。内层 pw<=x/p 恰好保证新的 d 满足 d*Pmax(d)<=n；反之每个满足条件的 d 都能由唯一分解产生。因此 n>=1 时调用次数恰为 R(n)+1，总循环和调用开销为 Θ(1+R(n))。计数是随整数路径而变的，不是 O(sqrt(n)) 个整除商各处理一次。测试对 n<=1000 用最大质因子数组独立枚举 R(n)，核对了这一等式。

预处理质数幂和表的工作量为 Θ(n^(3/4)/log(n+2))，再加 O(sqrt(n)*log log(n+2)) 的埃氏预筛。因此完整时间为

```text
T(n) = Θ(n^(3/4)/log(n+2) + R(n))。
```

R(n) 的渐近增长可进一步说明，不能停留在“保守 O(n)”：

1. 显然 R(n)<=n/2。固定任意整数 k，取 k 个不超过 n^(1/(k+1)) 的不同质数，它们的乘积 d 都满足 d*Pmax(d)<=n。按质数数量估计，R(n)=Ω(n^(k/(k+1))/log^k(n))。
2. 因而对任意固定 α<1，总能选取固定 k 使 R(n)/n^α 趋于无穷。不存在固定 δ>0，让这份无记忆化递归具有 O(n^(1-δ)) 的保证。尤其取 k=4，已足以反驳将它整体记作 O(n^(3/4)/log n)。
3. 又可证明 R(n)=o(n)：固定 A>2，将 d 分为 d<=n/A 和 d>n/A。前者至多 n/A 个，后者必须仅含不超过 A 的质因子，至多 O((log n)^π(A)) 个。先让 n 增长，再令 A 任意大，得到 R(n)/n→0。

所以当前完整时间在指数意义上是 **n^(1-o(1))**，同时严格为 o(n)；它不是一个具有固定节省幂次的算法。这是随同样算法增长的渐近结论，不意味着 n<=10^10 时就慢。

反向 DP 则把每个 (质数阶段,整除商) 合并：e=1 的更新量与前向筛相同，为 Θ(n^(3/4)/log n)；e>=2 的每层至多 O(n^(2/3)/log n)，指数层数 O(log n)，其总量仍被前者支配。因此普通反向 DP 的完整时间为 O(n^(3/4)/log(n+2))。两版空间均 O(sqrt(n))，DP 多一张整除商表。

## 结论与复现

这组输入和实现上，递归版全程更快；n=10^10 时，反向 DP 约慢 1.60 倍，多用 800000 字节的数组缓冲。原因与计数一致：该规模递归只展开约 630 万节点，而 DP 执行约 2470 万次幂转移。复杂度更好的 DP 到更大规模才可能抵消这种常数与状态数量差异，本文没有测出交叉点，也不把这些数字推广到所有实现或硬件。

验证时，两版均通过 1001 个连续前缀、100 个随机前缀的独立分解参考、大数一致性、题面样例和交错重建；节点公式另用最大质因子枚举核对。普通严格编译与 ASan/UBSan 均通过。计时阶段使用普通 O2 二进制。未提交在线评测。

这里不存在可以随意排列的数组或图，唯一输入是 n。递归节点数 R(n)+1 随 n 单调，而且相邻 n 的调用数至多增加 1：若新加入的节点满足 d*Pmax(d)=n，则 Pmax(d)=Pmax(n)，候选 d 只能为 n/Pmax(n)。因此把 n 选成某个素数、平方数或多因子整数，不会让节点数在相近规模下突然暴涨。

对“是否存在更慢输入”的结论是：**本次未找到，未证明不存在**。原比较没有覆盖其他硬件、不同常数优化的 DP、不同目标函数或多查询复用接口，不能据此宣称递归普遍更快。

## 用户提供的记忆化版本评估

2026-11-05，记录为历史实验，未增加正式模板文件，也未修改 min25.cpp。原始数据、编译选项及被测源码快照见 [min25_memo_review.json](min25_memo_review.json)。实验版本与用户的固定大哈希实现不同，不能把下列用时当成用户原代码的测量结果。

原代码在 `#define int long long` 下，Hash 的 heads、key、val、next 四组数组合计 `8*(10000019+3*10000000)=320000152` 字节，约 305.18 MiB，尚未计入其余数组就超过 P5325 的 250 MB 限制。节点从 1 开始而数组长为 M，最多只有 M−1 个合法节点，newnode 没有容量检查。init 也没有清空 Pr、筛表和缓存，因此不能交错重建或修改系数后复用。

内部允许负余数，所以 -1 可能是合法缓存值，不能同时用作“未计算”标记。一个可复现例子是 `init(2,-1,0,0)` 后 `calc(2)`：S(2,0) 恰为 -1，连续调用仍会重新计算。此处本身造成重复计算，不直接造成答案错误。状态编码 `(x<<20)+i` 在题目 n<=10^10、i<=9592 且使用 i64 的范围内安全；直接改为 int 则会溢出，不能只照搬原来的宏用法。

为单独评估记忆化价值，实验以当前 Min25 为基线，保留完全相同的两列质数和预处理与递归转移，仅加入 `unordered_map<i64,int>`。用 find 判断存在性，递归结果先存局部变量，返回时写缓存，solve 重建时清缓存；键为 `(x<<14)+i`，14 位能容纳本例全部质数下标。这是依赖 n<=10^10 的实验编码，扩大范围时必须重新检查。

环境为 AMD Ryzen 7 H 260、GCC 15.2、GNU++20 O2，绑定逻辑 CPU 2；Wall、Wextra、Wconversion、Werror 全部启用。两版串行运行，每个场景先各预热一次，然后各测 7 次，交错运行顺序，取中位数。每次为独立进程，计时包含对象构造、预处理、分配、所有查询、缓存释放及对象销毁，排除进程启动与输入输出。峰值 RSS 使用各进程的 VmHWM，含运行时与分配器开销。该实验只有下面两种查询分布，不覆盖更多 n、更多目标函数或密集查询的所有情况。

单次求和的 7 次时间范围分别为 109.742–133.512 ms、1555.316–1625.918 ms；100 次查询分别为 537.958–674.845 ms、2021.541–2385.652 ms。记忆化的复用有效，但这两组实验中哈希访问、分配和缓存销毁抵消了收益。实验版另外通过现有 test_min25.cpp 的 3207 组独立前缀、917602 项表值、8440 项受限递归、样例、大数相邻差及重建检查；本次没有对实验版运行 ASan/UBSan，也没有提交在线评测。

现有 calc 已能查询同一根 n 的正整除商，这不是记忆化版本新增的适用范围。缓存键没有包含构建根 n，因此只能在同一次构建内复用；不能把任意 x 当成整除商传入，更不能跨不同根的重建保留缓存。若要计算所有整除商的块筛前缀，反向 DP 本身会留下对应前缀表，可以优先评估该方向，而不是默认大哈希更快。

多项式系数 w0、w1、w2 是把本例的 F(p^e) 改成同一个二次多项式，需多维护常数项质数计数列；它不构成不同筛法，也不是任意积性函数接口。考虑纸质资料与现场手写成本，本次保留简洁的原递归模板，不单开这份记忆化模板。这个取舍基于当前需求和实测，未证明记忆化在其他实现、硬件或查询分布下都无收益。

需要复现实验时，可从 JSON 的 source_snapshots 导出 original.hpp、memo.hpp、bench.cpp；三个文件放在同一临时目录，以记录的 flags 编译 bench.cpp，然后串行执行 `taskset -c 2 ./bench plain 10000000000 1`、`taskset -c 2 ./bench memo 10000000000 1`。最后的参数改为 100 即为第二种场景，预热、重复和统计方式同上。JSON 内另存本次真实 s.cpp 公共部分及各文件哈希，用于区分历史实验和日后修改。
