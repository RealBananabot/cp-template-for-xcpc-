## 扩展欧几里得与模逆元

代码：[exgcd.cpp](exgcd.cpp)。保留原递归算法和交换输出引用的写法，不依赖模整数封装或预处理。

```cpp
int x, y;
int g = exgcd(30, 18, x, y); // g=6，30*x+18*y=6
int a = inv(3, 11);         // 4，调用者保证非负且可逆
int b = safe_inv(-3, 11);   // 7
int c = safe_inv(2, 4);     // -1，无逆元
```

### 接口与边界

- `template<class T> T exgcd(T a, T b, T &x, T &y)`：T 为 `int` 或 `i64`，要求 a、b 非负；输出满足 `a*x+b*y=gcd(a,b)` 的一组整数系数，并返回非负 gcd。`x`、`y` 必须引用不同变量；系数由递归过程决定，不承诺最小绝对值或归一化。所有参数使用同一种 T。
- 与原代码相比，返回类型从 `void` 改成对应整数类型，函数改为类型模板以供扩展 CRT 复用；原先参数类型一致的普通调用可以保留。`inv`、`safe_inv` 的接口仍为 int；只有 `exgcd` 同时支持非负 i64，负数参数不属于它的适用范围。
- `exgcd(0,0,x,y)` 返回 `0` 并输出 `(1,0)`；`exgcd(a,0,x,y)` 输出 `(1,0)`；当 `b>0` 时，`exgcd(0,b,x,y)` 输出 `(0,1)`。不使用 `abs`，避免 `INT_MIN` 取绝对值溢出。
- `int inv(int x, int p)`：沿用用户原递归求逆元写法，省去结果上冗余的 `res %= p`；要求 `0 <= x <= INT_MAX`、`1 <= p <= INT_MAX`，且调用者保证 `gcd(x,p)=1`；返回 `[0,p)` 内的唯一逆元。不检查可逆性，也不在调用 `exgcd` 前归一化 x；允许 x 不小于 p。负数输入及不可逆输入不属于这个接口的适用范围。
- `int safe_inv(int x, int p)`：`x` 可为任意 `int`（包括 `INT_MIN`），要求 `1 <= p <= INT_MAX`；先将 x 归一化到 `[0,p)`，可逆时返回该区间内的唯一结果，不可逆时返回 `-1`。两个求逆元函数均不要求模数为质数。
- 两个求逆元函数在 `p=1` 时均返回 `0`，采用 `x*r ≡ 1 (mod 1)` 的约定；`p>1` 时，零的逆元不存在。`p<=0` 对两者都是非法调用，`safe_inv` 也不检查非法模数。
- 三个函数均无持久状态，可重复调用；只有 `exgcd` 修改输出引用，不保存输入引用。不涉及数组、节点、容量或区间下标。

### 正确性、范围与复杂度

递归子问题满足 `b*y+(a%b)*x=g`，代入 `a%b=a-(a/b)*b` 即得 `a*x+b*(y-(a/b)*x)=g`。当 g=1 时，归一化 x 系数即可得到逆元；`inv` 依赖调用者保证 g=1，`safe_inv` 则显式检查并在 g 不为 1 时返回 `-1`。

在所选整数类型的非负范围内，递归得到的系数及更新中间值均可用该类型表示。设其最大值为 H（int 为 `INT_MAX`，i64 为 `LLONG_MAX`）。对 `a,b>0`，归纳证明返回系数满足 `|x| <= b/g`、`|y| <= a/g`，其中 `g=gcd(a,b)`：

- 记 `q=a/b`、`r=a%b`。若 `r=0`，本层返回 `(x,y)=(0,1)`，满足界限，更新中的乘积为 0。
- 若 `r>0`，设子调用 `exgcd(b,r,...)` 返回系数 `(u,v)`。归纳假设给出 `|u| <= r/g`、`|v| <= b/g`；本层先有 `x=v,y=u`，再执行 `y-=q*x`。
- 乘积满足 `|q*v| <= q*b/g <= a/g <= H`；减法结果满足 `|u-q*v| <= r/g+q*b/g = a/g <= H`。此外 `|x|=|v| <= b/g <= H`，归纳成立。这里所有界限按数学整数理解，并不需要在代码中计算这些界限。
- `b=0` 直接返回；`a=0,b>0` 时 `q=0`，返回 `(0,1)`。这些退化情况也不会溢出。除法与取模的除数仅在 `b>0` 时使用，且没有 `INT_MIN/-1` 情形。

`inv`、`safe_inv` 中均省去 `res %= p`：当 `p>1` 且 gcd 为 1 时，由上述系数界限得到 `|res| <= p`；若 `res=±p`，则 Bézout 等式左边能被 p 整除，不可能等于 1，因此实际上 `-p < res < p`。`p=1` 时本实现直接得到 `res=0`。所以只需在 res 为负时加一次 p，便得到 `[0,p)` 内的结果，并且加法不会溢出。`safe_inv` 已检查 gcd 为 1，因此同样适用；输入端的 `x %= p` 和负数修正仍保留，以支持任意 int 输入。

不能由此推断调用方的 `a*x+b*y` 也能用原类型计算：int 输入验证时须先扩展为 `i64(a)*x+i64(b)*y`，i64 输入验证时使用 i128。`safe_inv` 中模数为正，余数的绝对值小于 p，负余数加 p 后落在 `[0,p)`；归一化均不会溢出，包括原输入 x 为 `INT_MIN` 时。`exgcd` 自身及两个 int 求逆元函数无需更宽的现场运算类型。

以固定宽度整数运算为 O(1)，`exgcd` 最坏时间与递归栈空间均为 `O(log(max(a,b)+2))`；`inv`、`safe_inv` 均为 `O(log(p+1))`。除递归栈外只使用常数空间，无初始化开销。

### 两个求逆元接口的区别

保留的 `inv(2,4)` 会返回 `1`，但该输入不满足可逆前提，结果没有逆元含义；`safe_inv(2,4)` 返回 `-1`。`inv(-1,5)` 的负数输入也违反前提；应使用 `safe_inv(-1,5)`，返回 `4`。只有 `safe_inv` 提供负数归一化和不可逆检测，不将它们混同为原 `inv` 已实现的功能。

## 扩展 CRT

代码：[excrt.cpp](excrt.cpp)。先粘贴 [exgcd.cpp](exgcd.cpp) 中的 `exgcd` 函数模板，再粘贴本文件；两个求逆元函数不是必需依赖。保持逐条合并的原算法，通过 exgcd 的返回值获取 gcd，省去原实现额外的 gcd 调用；定义 `using i128 = __int128`。

### 接口与边界

`pair<i64,i64> crt_merge(const pair<i64,i64> &A, const pair<i64,i64> &B)`。

- 每个 pair 按 `{模数,余数}` 存储，表示 `x ≡ 余数 (mod 模数)`。直接使用 `pair<i64,i64>`，不新增结构体；缺省源中的 `pi` 是 `pair<int,int>`，不足以保存本接口的整数范围。
- 有效输入的模数在 `[1,LLONG_MAX]`，不要求互质；余数可以是任意 i64，包括负数和 `LLONG_MIN`，函数先归一化。零模数和其他负模数不支持。
- 要求两个模数的最小公倍数不超过 `LLONG_MAX`。这是调用前置条件，模板不提供溢出检测或更大整数结果；不能将超过范围混同为数学上无解。
- 有解返回 `{lcm,最小非负解}`，余数在 `[0,lcm)`；无解返回 `{-1,-1}`。该标记与任意有效信息继续合并都返回 `{-1,-1}`，包括与自身合并。
- `{1,0}` 是初始信息，表示没有约束。零条方程最终为 `{1,0}`；单条方程返回归一化后的结果。重复方程、模数为 1、一个模数整除另一个模数均支持；无解条件为余数之差不能被 gcd 整除。
- 不修改输入、不保存引用、无持久状态；可重复调用，也可从上一次合并结果继续追加方程。不提供方程删除或在线修改已有方程的接口。

### 使用方式与题目范围

将下面代码放入 `s.cpp` 的 main 中；`n` 个输入 pair 的顺序同样为 `{模数,余数}`。

```cpp
int n;
cin >> n;
pair<i64, i64> c{1, 0};
rep(i, 1, n){
	i64 k, r;
	cin >> k >> r;
	c = crt_merge(c, {k, r});
}
cout << c.se << '\n';
```

[洛谷 P4777](https://www.luogu.com.cn/problem/P4777) 要求最小非负解，保证有解；`n<=100000`，各输入模数在 `[1,10^12]`、余数在 `[0,10^12]`，全部模数的最小公倍数不超过 `10^18`。输入余数可能不小于模数，本接口直接支持。上例在无解时输出 -1；这属于通用模板的扩展约定，题目不会出现无解。

### 正确性与算术范围

设归一化后两信息为 `(a,r)`、`(b,s)`，`d=s-r`，`g=gcd(a,b)`。必须且只需 `g | d` 才有解。exgcd 给出 `a*x+b*y=g`，乘以 `d/g` 可知 `r+a*x*(d/g)` 同时满足两条同余式。以 `m=lcm(a,b)` 取模并修正负余数，即得到唯一的最小非负解。

余数先归一化，因此 `d` 在 i64 范围内；`a/g*b` 因 lcm 的前置条件可用 i64 计算。乘法从 `i128(x)` 开始扩展，避免在 i64 中先溢出。由系数界限 `|x|<=b/g` 得到 `a*|x|<=m`，于是完整表达式的绝对值至多 `m*|d/g|+r`；当 `m<=LLONG_MAX` 时小于 `2^126`，整个三因子乘法与加法均在有符号 i128 范围内。取模后结果绝对值小于 m，才安全缩回 i64；负值加 m 也不会溢出。

原实现只在发生冲突的当次合并返回 `{-1,-1}`，后续仍可能将它当成负模数继续计算。本版先检查无解标记，保证它在连续合并中保留。P4777 保证有解，原实现在该题范围内不会触发此问题。

### 复杂度与验证

有效信息单次合并最坏 `O(log(min(a,b)+1))` 时间，递归栈空间同阶；其余工作与空间为常数，无预处理。无解标记短路为 O(1)。顺序合并 n 条方程，若全部模数的 lcm 为 L，总时间上界为 `O(n log(L+1))`，峰值辅助空间 `O(log(L+1))`，包含递归栈；流式读取时无需保存全部输入。

## Lucas：质数模数的组合数

代码：[lucas.cpp](lucas.cpp)。只依赖缺省源中的 `i64`、`vi`、`rep`、`per` 和标准库；不依赖 `mint.cpp`、快速幂、逆元或扩展 CRT。

保留原算法的“阶乘、逆阶乘预处理加 Lucas 分解”，以 `struct Lucas` 保存当前模数和数组，辅助函数保留 `C`，最终查询入口改名为 `solve`。原全局数组与单独的 p 参数改为对象状态，避免多模数之间混用预处理表；递归分解方式不变。

### 接口与边界

- `Lucas l(p)`：p 必须为质数，`2 <= p <= INT_MAX`，且有足够时间和内存完整预处理 `[0,p)`。p 是模数，同时决定两个数组各有 p 项；不检测质数，不支持合数、质数幂或模数 1。
- `l.C(int m,int n)`：要求 `0 <= m < p`；返回 `C(m,n) mod p`。n 小于 0 或大于 m 时返回 0；不支持把 m 不小于 p 的一般组合数交给此函数。
- `l.solve(i64 m,i64 n)`：要求 `0 <= m <= LLONG_MAX`；返回 `C(m,n) mod p`，n 为任意 i64，n 小于 0 或大于 m 时返回 0。`solve(0,0)=1`、`solve(m,0)=solve(m,m)=1`。m、n 分别是组合数的上参数、下参数，顺序与原代码一致。
- 返回值均在 `[0,p)`，不涉及多解取舍、节点编号或输入数组。阶乘和逆阶乘的下标都是 `[0,p)`，`fac[0]=ifac[0]=1`。
- 同一对象可重复查询，不修改输入或预处理状态，不保存外部引用；多个不同模数对象相互独立。需要换模数时新建对象或执行 `l=Lucas(q)`；没有原地 `init` 或扩容接口，不应直接修改 p、fac、ifac。
- 对象重新赋值会先构造新对象，再替换旧对象，峰值数组空间包含新旧两组表；正常查询不分配数组。公共成员的直接修改不在接口保证内。

### 使用方式与题目范围

[洛谷 P3807](https://www.luogu.com.cn/problem/P3807) 要求 `C(n+m,n) mod p`，保证 p 为质数；`1 <= n,m,p <= 100000`、测试组数不超过 10。将下面代码放入 `s.cpp` 的 main 中：

```cpp
int T;
cin >> T;
while(T--){
	int n, m, p;
	cin >> n >> m >> p;
	Lucas l(p);
	cout << l.solve(i64(n) + m, n) << '\n';
}
```

同一个 p 的多个查询可复用对象；以上题目示例每组独立构造，没有跨测试组缓存。一般使用时，若调用者用 i64 输入自行形成 `n+m`，须保证和不超过 `LLONG_MAX`，函数不会检查已经溢出的实参。

### 正确性与算术范围

由于恰好预处理到 `p-1`，Wilson 定理给出 `(p-1)! ≡ -1 (mod p)`，它的逆元仍为 -1，因此直接令 `ifac[p-1]=fac[p-1]`，再倒推其余逆阶乘；p=2 同样成立。这省去原代码中的一次快速幂及独立 `inv` 函数，不改变质数模数的适用范围。若以后把预处理终点缩小到任意小于 `p-1` 的位置，此赋值不能直接沿用。

`C` 用阶乘与逆阶乘计算一位组合数；`solve` 根据 Lucas 定理，将两参数按 p 进制逐位分解并相乘。用户原代码中的 `calc(0,1,p)` 会在检查组合数越界前返回 1，本版显式规定 n 大于 m 时返回 0；题目实际调用的下参数不大于上参数，原代码在题目范围内未发现算法错误。

所有表项和答案用 int 保存，查询参数用 i64。乘法先扩展到 i64，并在第三个因子参与前取模，每次实际乘法至多为 `(p-1)^2 < 2^62`，不依赖原代码的全局 `#define int long long`。`m%p`、`n%p` 在非负参数通过检查后均在 `[0,p)`，才安全缩回 int；查询内部不计算 `m+n`。

### 复杂度与验证

构造包含两个 vector 的容量初始化、阶乘表和逆阶乘表，总计 O(p) 时间、O(p) 空间；32 位 int 下表内元素共 `8p` 字节，不包含少量对象与分配器开销。完整预处理使本模板仅适合可接受 O(p) 资源的质数，不能因为参数类型支持 int 就认为它适合任意大质数。

`C` 单次 O(1) 时间和额外空间；`solve` 最坏时间与额外递归栈空间均为 `O(1+log_p(n+1))`，在合法非负 i64 范围内最多 64 层调用，无临时数组。n=0 或越界时为 O(1)。这里 `n+1` 仅用于数学复杂度表达，不在程序中计算；对象持有的 O(p) 表另计。若多组数据均重新构造，总时间为 `O(sum(p)+sum(1+log_p(n+1)))`，不能只计算查询代价。

## exLucas：任意正整数模数的组合数

代码：[exlucas.cpp](exlucas.cpp)。先粘贴 [exgcd.cpp](exgcd.cpp) 的 `exgcd` 与 `inv`，再粘贴本函数；不需要 `safe_inv`、快速幂、`Lucas` 或 `crt_merge`。缺省源依赖为 `i64`、`vi`、`rep` 和标准库。

保留原来的质数幂分解、去除质因子的阶乘和合并答案算法，整理成单个直接函数；删除 `Sub`、`Int`、乘法封装、重复求逆元实现和所有质数幂对象的保存。每次只处理一个质数幂，用局部 lambda 返回 `{去除 p 因子的阶乘,阶乘中 p 的指数}`，处理完立即释放该表。

### 接口与使用方式

`int exlucas(i64 m,i64 n,int mod)` 返回 `C(m,n) mod mod`，上参数、下参数的顺序沿用原代码。

- 要求 `0 <= m <= LLONG_MAX`、`1 <= mod <= INT_MAX`；mod 可以为质数、质数幂或一般合数。仍需有足够时间和内存完成模数因子的完整表，实际定位是 P4720 的小模数，不适合任意大 int 模数。
- n 可为任意 i64；`n<0` 或 `n>m` 返回 0。`mod=1` 始终返回 0；其他模数下 `exlucas(0,0,mod)=1`、`exlucas(m,0,mod)=exlucas(m,m,mod)=1`。
- 返回值在 `[0,mod)`。无持久状态，不修改输入、不保存引用，可连续交替调用不同模数；每次调用都重新分解并预处理，没有跨查询缓存、独立预处理对象或在线修改接口。
- 对质数幂 `q=p^a`，局部数组 f 有 q 项，`f[i]` 为 `[1,i]` 内所有不被 p 整除的数之积模 q，`f[0]=1`，下标范围 `[0,q)`。q 是实际数组长度，不是用户另行传入的容量。

[洛谷 P4720](https://www.luogu.com.cn/problem/P4720) 输入的是 `n,m,p`，求 `C(n,m) mod p`，范围为 `1 <= m <= n <= 10^18`、`2 <= p <= 10^6`，模数不保证为质数。main 中按题目顺序调用：

```cpp
i64 n, m;
int p;
cin >> n >> m >> p;
cout << exlucas(n, m, p) << '\n';
```

### 原实现的问题与修正

1. `Int(int x=0)` 只初始化 w，没有初始化 c。`fac[0]=1` 和乘法时从整数构造的临时 Int 都会带有未初始化的指数，随后 `mul` 读取它，属于未定义行为。本版不再使用该类型，所有计数显式从 0 开始。
2. 原 `Fac` 把每整块的单位乘积写成 -1，但模 `2^a`、`a>=3` 时该乘积是 1。例如 `q=8`，单位乘积 `1*3*5*7 ≡ 1`。即使先将原 Int 的 c 初始化为 0，原公式仍得到 `Fac(8).w=5`、`Fac(4).w=3`，最终把 `C(8,4) mod 8` 算成 2；正确结果为 `70 mod 8=6`。测试固定保留此反例。

本版从预处理表直接取真实块乘积 `f[q-1]`。模 q 的可逆元素与其逆元配对可知，所有可逆元素之积的平方为 1，所以整块的幂只取决于块数奇偶；原来的奇偶优化仍保留，但不再假定该乘积总为 -1。

### 正确性与算术范围

对每个 `q=p^a`，局部 `fac(x)` 迭代计算去除 x! 中全部 p 因子后的单位部分，以及 `v_p(x!)=sum floor(x/p^j)`。将上参数、下参数和差的单位部分相除，再乘回 `p^(v_p(C(m,n)))`，得到模 q 的组合数。分母单位部分与 q 互质，因此已有 `inv` 的前提满足；指数达到 a 时结果为零，循环在此时短路。

不同质数幂 q 两两互质，设 `k=mod/q`，则 `k*inv(k mod q,q)` 模 q 为 1、模其他质数幂为 0。直接累加每项贡献即可；这是原合并公式，不额外调用通用 `crt_merge`，也无需 i128。

模数、数组和试除变量使用 int，计数、单位部分和中间乘法使用 i64。q 在乘 p 后仍整除 mod，因而 `q*=p` 不溢出；试除只在不整除时递增 p，提取最后一个因子后直接退出，即使 mod 为 `INT_MAX` 也没有末尾自增溢出。f 的乘法、单位部分乘法与乘回 p 的乘法均小于 `mod^2 < 2^62`。

每个 `fac` 中的计数为阶乘质因子指数，不超过原参数；对 p=2 的最大情形也小于等于 `LLONG_MAX`。检查 n 的范围后才计算 `m-n`，三个阶乘指数依次相减不会超出范围。CRT 项先有 `k*inv(k mod q,q)<mod`，再乘 `r<q`，最后加 `res<mod`；总量小于 `mod^2+mod<2^62`，因此最终合并也不需要 i128。只在值已取模且小于 int 模数后才缩回 int。

### 复杂度与验证

设模数分解为互质质数幂 `q_i=p_i^a_i`，共有 s 项。试除到最后一个质因子，代价不超过 `O(sum q_i)`，与必须建立的表同阶；特意不增加平方根后剩余质因子的额外处理分支。每张表包含 vector 初始化和线性前缀积，合计 `O(sum q_i)`。三次去因子阶乘合计每项 `O(1+log_{p_i}(m+1))`，两次逆元每项 `O(log q_i)`，乘回质因子最多 `a_i` 次后变为零。

总时间为 `O(sum q_i + sum(1+log_{p_i}(m+1)+log q_i+a_i))`，可宽松界为 `O(mod+log(mod+1)*log(m+2))`；不能只计分解或查询代价。只保存当前 q 的表，峰值辅助空间 `O(max q_i)`，包含该表、局部计数及返回 pair。阶乘迭代本身只用常数空间，所依赖 inv 的 exgcd 使用 `O(log q_i)` 递归栈，也包含在上述空间界内。32 位 int 下主要表元素约 `4*max q_i` 字节。mod=1 或非法下参数立即返回，时间空间均 O(1)。

## Miller–Rabin：int 与 i64 素性测试

int 专用版在 [miller_rabin_int.cpp](miller_rabin_int.cpp)，i64 版已整合到 [pollard_rho.cpp](pollard_rho.cpp)，原独立 `miller_rabin.cpp` 已合并删除。两者都基于缺省源使用，保留 `PR` 命名空间、`PR::qpow`、`PR::isprime`；需要完整分解时只粘贴 `pollard_rho.cpp` 即可。int 专用版也可与整合版同时粘贴，构成 int、i64 重载。

i64 版的七底数表旁同时保留了注释形式的 `const int T[]{2,7,61};`，仅判定 int 范围时可替换使用；默认仍启用七底数，覆盖完整正 i64。

### 固定底数与保证范围

| 文件 | 判定接口 | 固定底数 | 乘法中间类型 |
|---|---|---|---|
| `miller_rabin_int.cpp` | `bool PR::isprime(int x)` | `2,7,61`，3 轮 | i64 |
| `pollard_rho.cpp` 内置 | `bool PR::isprime(i64 x)` | `2,325,9375,28178,450775,9780504,1795265022`，7 轮 | 有符号 i128 |

三底数组已知适用于 `n<4759123141`，覆盖完整正 int；七底数组已知适用于 `n<2^64`，覆盖完整正 i64。依据为 [SPRP 底数记录](https://miller-rabin.appspot.com/) 和 [Forišek–Jančina 论文 Theorem 3](https://ceur-ws.org/Vol-1326/020-Forisek.pdf)。这里采用可核查记录中覆盖相应范围的最少固定底数轮数：两底数记录上界 `1050535501` 未覆盖 `INT_MAX`，六底数记录上界 `585226005592931977` 未覆盖 `LLONG_MAX`；这不是任意底数选择下的绝对最优性证明。依赖哈希表按输入选择底数的方案属于另一种取舍，本模板不引入查表。

底数集合的数学保证范围与函数的类型范围必须区分：当前两个函数分别只接收有符号 int、i64，i64 版不支持完整 u64，也不能通过将超出 `LLONG_MAX` 的值强制转换来扩展范围。若要完整 u64，还必须同步更换参数类型与乘法为 u128。

### 接口、边界与正确性

- `isprime` 对完整相应有符号类型范围有定义：负数、0、1 返回 false；2 返回 true；其余偶数返回 false。无持久状态、不修改输入、不保存引用，可重复调用，无数组容量参数。
- 先排除上述边界，才计算 `x-1` 和它的尾零数，此时 x 为至少 3 的奇数，`__builtin_ctz`／`__builtin_ctzll` 的实参非零；`x-1` 不溢出。
- 对每个底数先执行 `a%=x`。a 为 0 时只通过当前一轮，继续检查其他底数；不能因此提前判定整个输入为质数。原来的“底数不小于 x 就通过”改成此规则，以直接满足固定底数保证所需的全部剩余类检查。
- 将 `x-1` 的二进制分解放到逐底数循环之外；每轮保留快速幂和连续平方的 Miller–Rabin 算法。初值为 1 或 −1 时通过，后续至多平方 t−1 次寻找 −1，避免原实现最后一次额外平方。
- 在给定类型范围内，该固定底数算法为确定性判定，不使用随机数；正确性保证依赖上述已验证的底数界限。随机测试本身不能建立该范围保证。
- `PR::qpow(x,y,mod)` 是同类型的模幂辅助函数，要求 `0<=x<mod`、`y>=0`、`mod>=2`；指数为 0 返回 1，包括底数为 0 的情形。调用 `isprime` 不需要先调用它。

int 版的所有模乘先扩展为 i64，乘积小于 `2^62`；i64 版定义 `using i128=__int128`，模乘先扩展为 i128，乘积小于 `2^126`。取模结果确定在 `[0,x)` 后才缩回原整数类型，不用浮点模乘或近似商。位移仅作用于正数，位数分别不超过 30、62。

## Pollard–Rho：有重复项的不降质因子数组

代码：[pollard_rho.cpp](pollard_rho.cpp)。文件内直接包含 i64 Miller–Rabin、模幂、Pollard–Rho 和最终 `solve`，保持七底数保证；只需缺省源中的 `i64`、`pb`、`rep` 和标准库，不再粘贴其他数论文件。素性判定、模幂和分解接口保持原名，不使用条件编译或跨文件 include 隐藏依赖。

### 返回类型与接口

- `vector<i64> PR::solve(i64 x)`：要求 `1 <= x <= LLONG_MAX`，返回所有质因子按不降顺序排列的 vector，重复因子逐个保留。例如 `solve(12)` 为 `{2,2,3}`，`solve(9)` 为 `{3,3}`，质数返回 `{x}`，`solve(1)` 返回空数组。0、负数和完整 u64 范围不支持。
- 因子数组直接写作 `vector<i64>`，不另设别名。调用方用 `auto a=PR::solve(x)` 或 `vector<i64> a` 接收；缺省源的 `vi` 仍为 `vector<int>`，不能用它接收完整范围结果。
- `PR::rho(x)` 是内部找因子函数，前提为合数，成功仅返回 `1<g<x` 的因子；不是质数判定接口。`PR::work(x,a)` 为内部递归追加函数，最终接口仍使用 `solve`，它会创建新的返回数组并在末尾排序。
- 输入按值传递，不修改原输入、不保存外部引用；每次返回独立数组，前一次的结果在后续调用后仍有效。连续调用无需清空 map 或数组；随机引擎状态会继续推进。
- 因子数组从 0 开始，完整正 i64 最多包含 62 项；空数组对应 1，读取 `.back()` 前须先判断非空。本题输出所有因子，不再输出 `Prime` 或仅最大质因子。

### 算法、重试与算术范围

保留原来的 Brent 式倍增长度和每 127 步批量 gcd，寻找因子后递归分解两部分。移除全局计数 map，直接在局部数组追加质因子，最后统一排序。偶数直接取因子 2，避免把这一退化情况交给随机迭代。

原实现遇到 `gcd(prd,x)=x` 会再次调用 `work(x)`，问题没有缩小；例如分解 9 时若首个 c=0，轨迹一直为 0，乘积为 0，gcd 为 9。这种失败可能反复递归，深度没有原算法意图中的保证。本版此时退出当前轨迹并重新随机 c，只有得到真因子才进入递归；测试找到使首个 c 为 0 的种子，固定覆盖此分支。

原差值 `q-p+x` 可能接近 `2x`，超出 i64。本版使用 `abs(q-p)`，因为两轨迹点都在 `[0,x)`，差值绝不等于 `LLONG_MIN`，减法与取绝对值安全。模乘与 `q*q+c` 均先扩展至 i128，绝对值小于 `2^126`；取模后再缩回 i64。

一次轨迹的 goal 只取 `1,2,...,2^20`，最多执行 `2^21-1` 次迭代；如果仍没有因子就重试。goal 最后一次自增到 `2^21`，不会发生原来无限倍增导致的有符号溢出。这个上限是重启策略，不是分解总迭代次数的保证。

随机引擎为 `mt19937_64 rnd(3663)`，便于复现；可调用 `PR::rnd.seed(seed)` 更换种子。`rnd()%x` 转换前已保证结果在 `[0,x)`，允许 c=0，但轻微取模偏差与固定伪随机序列都不构成严格均匀随机映射假设。返回结果的正确性由 gcd、递归真因子与确定性 Miller–Rabin 保证，随机性只影响找到因子的时间。重复失败会继续重试，没有有限的最坏重试次数承诺。

### QOJ 458 调用方式

[QOJ 458：质因数分解](https://qoj.ac/contest/3936/problem/458/statement/zh_cn) 已通过浏览器核对：`T<=1000`，`2<=N<=10^18`；每组输出全部质因子，按不降顺序空格分隔，保留重复项，不输出因子数量。样例为 `2 -> 2`、`9 -> 3 3`、`30 -> 2 3 5`。

## BSGS：一次 gcd 约去非互质部分

代码：[bsgs.cpp](bsgs.cpp)。保留原代码“先检查对数个小指数，一次取 gcd，再做普通 BSGS”的方法，仅保留一个直接函数；互质和非互质情形调用相同接口，不另写普通 BSGS 或 exBSGS。仅依赖缺省源中的 `i64`、`rep`、`se` 和标准库；模幂写在函数内，不依赖其他数论模板、逆元或 PBDS。

### 接口与边界

`int bsgs(int a, int p, int b)`：返回 `a^x ≡ b (mod p)` 的最小非负整数 x，无解返回 `-1`。参数顺序对应题目的底数、模数、目标余数。

- 支持 `0 <= a,b <= INT_MAX`、`1 <= p <= INT_MAX`，入口归一化 a、b。模数不必为质数，底数不必可逆；不支持负数参数或 i64 模数。相比原来的 u64 形参，明确以 int 范围作为接口，并用 i64 处理乘法；原码也不能据 u64 形参就推断支持完整 u64 模数。
- 指数从 0 开始，采用 `a^0=1`（包括 `0^0`）。`p=1` 恒返回 0；`b%p=1%p` 返回 0。`p>1,a%p=0` 时，目标 1 返回 0，目标 0 返回 1，其余无解。底数为 1 时同样按该最小指数定义处理。
- 有解时返回值不超过原模数减一：幂序列只有 p 个余数，首次重复后不会出现新余数，任何可达余数的第一次出现都在 `[0,p)` 内。
- 参数按值传递，局部修改模数和余数，不修改调用者数据，不保存引用或外部状态。每次调用创建并销毁局部哈希表，可重复调用；没有批量查询、持久表或继续追加的接口。
- 表中的指数 j 从 0 开始，范围 `[0,B)`；重复余数覆盖为最大 j。B 不超过 46341，哈希桶和节点均在函数内申请，调用者无需提供容量。

### 为什么一次 gcd 就足够

令原模数为 M，`t=floor(log2(M))`。先直接检查 `x=0,...,t`，并留下 `z=a^t mod M`。记 `g=gcd(z,M)=gcd(a^t,M)`。M 中任意质因子的指数不超过 t，因此所有同时整除 a、M 的质因子及其完整幂次都包含在 g 中，`gcd(a,M/g)=1`。

对于剩下的指数 `x=t+y`，原式等价于 `z*a^y ≡ b (mod M)`。若 g 不整除 b，则无解；否则将 z、b、M 同除以 g，得到 `z'*a^y ≡ b' (mod P)`，其中 `P=M/g`，且 a、z' 均与 P 互质。这里的 `z'` 来自模幂余数除以 g，正好代表 `a^t/g mod P`，无须计算巨大整数 `a^t`。

只需把普通 BSGS 的巨步初值从 1 改为 z'：小步存 `b'*a^j`，巨步枚举 `z'*a^(iB)`，碰到相等余数即得 `y=iB-j`，答案为 `t+iB-j`。不必求 z' 的逆元。前面已经检查 y=0；有解时剩下的最小正 y 小于 P，`B=floor(sqrt(P))+1`、`i=1,...,B` 足以覆盖。

每个巨步对应连续指数区间 `[(i-1)B+1,iB]`，这些区间按递增顺序访问；同一个余数保留最大的 j，使当前区间的解最小，因此第一次命中给出全局最小解。不能把覆盖赋值随意换成只保留最早插入：例如 `bsgs(2,257,255)` 应返回 9，保留最小 j 会返回 25。约分后的初值系数也不能丢，例如 `bsgs(2,22,10)` 的答案为 5。

原代码在 P4195 的整数范围内，这一算法思路成立。整理时去掉无关的 mint、字符串指数模幂、调试宏、输出与全局表；以标准库 `unordered_map<int,int>` 替代 PBDS。无解直接用有符号 `-1`，避免原来先转换到 u64 再通过 `int(c)` 判断的写法。`prd==0` 的退出判断也不再需要：进入 BSGS 时 P>1，巨步初值与步长均可逆，巨步不会为 0。若约分后 P=1，原归一化目标必为 0，已在小指数检查中返回。

### 算术范围、复杂度与哈希

所有参与模乘的非负 int 值的乘积小于 `2^62`，先用 i64 乘法，再取正模数、缩回 int，安全。约分后 a 可能大于新模数，但仍处于原 int 范围，乘法界限不变。巨步乘积 `i*B` 可能略超 `INT_MAX`，因此答案表达式也先用 i64 计算；由最小解界限，最终返回值可以安全转换为 int。`__lg` 的参数始终为正；`p=1` 在早期检查中返回，不会进行除零或以 0 为参数求对数。

以固定宽度整数运算为 O(1)，小指数检查和一次 gcd 为 `O(log(M+1))`，内部模幂为 `O(log(P+1))`。令 `B=floor(sqrt(P))+1`，在哈希操作平均 O(1) 的模型下，建表、巨步查询和表的销毁共 O(B)，总时间为 `O(log(M+1)+sqrt(P))`。标准库哈希没有无条件最坏常数时间保证，恶意碰撞时整段 BSGS 最坏可达 `O(B^2)=O(P)`；当前 `std::hash<int>` 未加随机化，不能给它套用随机哈希的严格期望保证。

哈希表完整比较整数键，哈希碰撞不会导致错误答案，只可能降低效率。峰值空间 O(B)，包括 `reserve(B)` 的桶、实际键值节点及返回前的局部表；即使不同余数很少，预留桶也不能从空间分析中省略。其余变量与返回值为 O(1)，无递归。

## 最小原根：i64 试除版与 Pollard–Rho 版

两份是互斥实现，接口均为 `i64 primitive_root(i64 d)`，现场二选一，不同时粘贴或链接。

| 文件 | 模数上界 | 依赖与分解方式 |
| --- | --- | --- |
| [primitive_root.cpp](primitive_root.cpp) | `2^62-1`，包含 `10^18` 范围 | 仅缺省源与标准库；试除，模幂内置 |
| [primitive_root_pollard_rho.cpp](primitive_root_pollard_rho.cpp) | `2^63-1` | 先粘贴 [pollard_rho.cpp](pollard_rho.cpp)，复用素性判定、rho、分解与模幂 |

```cpp
i64 g = primitive_root(d); // 最小原根；不存在返回 -1。
```

### 共同接口与边界

- 两版均使用 i64 输入与返回值：试除版要求 `1<=d<=2^62-1`，PR 版要求 `1<=d<=2^63-1`。按 `1<=g<d`、乘法阶恰为 `phi(d)` 的定义返回最小原根；不存在返回 `-1`。`d<=1` 统一返回 `-1`，包括 0、负数和 `LLONG_MIN`，不把模 1 的平凡群另作特殊原根约定。试除版不检查正数上界，超出 `2^62-1` 属于不满足前置条件，不能当作已支持输入或数学上无根。
- `d=2` 返回 1，`d=4` 返回 3；其余正模数有原根当且仅当为 `p^k` 或 `2p^k`，p 为奇素数、k>=1。该分类可参见 [Stanford Math 152 课程记录](https://math.stanford.edu/~ksound/Math152A10/Math152.html)。
- 参数按值传递，不修改调用者输入，不保存引用或依赖输入生命周期。每次调用独立计算并返回标量，可重复调用；没有缓存、追加或多个模数共享预处理的接口。
- 试除版没有随机状态；PR 版调用会推进既有 `PR::rnd`。改变种子影响分解路径与耗时，不影响最小值。候选原根都按递增顺序确定性检查，PR 的素性判定沿用完整有符号 i64 范围的七底数版本。
- 无数组下标、区间、根节点或外部容量参数。局部因子数组均使用 `vector<i64>`，缺省源的 `vi` 仍为 `vector<int>`。

### 算法与最小值

保留原代码“判定存在性、求 phi 的不同质因子、递增检验候选”的结构。

特判 2、4 后，排除 4 的倍数；d 为偶数时取 n=d/2，否则取 n=d，此时 n 为至少 3 的奇数。只需找到 n 的一个素因子 p，再把 n 中的 p 除尽：余下为 1 当且仅当 n=p^k。因此判定不必完整分解 d，也没有再加入枚举幂次、整数开方或浮点校正。

试除版只枚举奇数到 sqrt(n)：第一个整除 n 的数必为素数；若没有，则 n 本身为素数。PR 版先作素性判定，遇到合数就调用 rho 取一个真因子，对该因子重复直到得到素数。两者最后都检查 n 是否为该素数的纯幂。

已知 n=p^k 后，`phi(d)=n/p*(p-1)`。其不同质因子就是 p−1 的不同质因子，以及 k>1 时补上的 p。两版都只完整分解 p−1，不再重复分解已知的 p 幂。试除版每次除尽一个质因子，直接得到不重复的列表；PR 版的返回值保留重数，因此另用 unique 去重。补入的 p 大于 p−1 的所有质因子，有序性不变。

对候选 g 先要求 `gcd(g,d)=1`。由 Euler 定理，阶整除 phi；对 phi 的每个不同质因子 q，检验 `g^(phi/q) mod d != 1`。若阶为 phi 的真因子，总能取到一个 q，使阶整除 phi/q；反之全部通过时阶只能等于 phi。因此判据充要。g 从 2 递增，首次通过即为最小值；原根为 1 的情形只有已特判的 d=2。

始终在原模数 d 下检验，不能直接把 p 的最小原根当作最终答案。例如 `primitive_root(40487)=5`，但 `primitive_root(40487^2)=10`，`primitive_root(2*40487^2)=13`。寻找任意原根或直接提升原根，不能保证这个最小值接口。

### i64 算术安全

两版输入、返回值、候选、试除变量、phi 和因子元素都使用 i64。phi 先除后乘，数学值不超过 n，因此 `n/p*(p-1)` 在 i64 内安全。

试除版的边界直接写 `p*p<=n`、`q*q<=v`。由 `d<=2^62-1`，试除计数器最多略过 sqrt(d)：奇数 p 最多到 `2^31+1`，其平方仍小于 `2^63-1`，包含退出时多走的一步；q 的自增同样安全。把 p 赋成大素数 n 后不再计算 p*p。找到素因子后每次整除都缩小正整数，除数始终为正。试除版没有转成 int 的中间值，也不依赖 unsigned 的回绕。若要扩展为完整 `2^63-1`，须把这些边界改为 i128 平方或除法比较。

两版的模幂都先用 `using i128 = __int128` 扩展乘法，乘积小于 `2^126`，取模后安全缩回 i64；试除版在函数内定义模幂，不必先写 Pollard–Rho 或 Miller–Rabin。候选满足 `2<=g<d`，指数非负，调用模幂的模数至少为 3。候选循环最后最多从 d−1 增到 d，不会继续自增至溢出；全程不取输入绝对值，也不计算 p^k 或 2p^k。

### 复杂度与使用规模

令 q 为 phi 的不同质因子数，C 为实际检验的候选个数。有根且未走 2、4 的特判时，C=最小原根−1，不能把最小原根当作常数。两版候选检验的最坏上界均为 `O(C*(q+1)*log(d+1))`，包括 gcd 与模幂。

试除版找素因子的最坏时间为 O(sqrt(n))，分解 p−1 最坏为 O(sqrt(p))，除尽幂次的总工作为 O(log(d+1))。总时间上界可写为 `O(sqrt(d)+C*(q+1)*log(d+1))`，特判的 2、4、d<=1、其他 4 的倍数除外，均为 O(1)。额外空间 O(q)，包含局部因子数组及其容量；模幂、试除与候选循环均无递归。试除版在声明的 `2^62-1` 上界内算术安全，但接近上界的大素数仍可能需要约十亿次试除，不能据“i64 类型”声称这类输入也高效。

PR 版令 F 为本次全部 PR 素性判定、找因子及 p−1 分解（含排序）的实际代价，总时间为 `F+O(log(d+1)+C*(q+1)*log(d+1))`。F 沿用 Pollard–Rho 的重试性质，没有无条件有限最坏重试次数保证；也没有把随机取任意原根的期望次数套到从小枚举的代码。峰值额外空间 O(log(d+1))，包含有重数的因子数组、去重后保留的原容量、PR 递归栈与排序栈，另有既有随机引擎的固定状态。

两版发现无根后均直接返回，不进入候选循环；均不使用与 d 成正比的筛表。不以实测速度替代上述复杂度，也不承诺每个 i64 输入都能快速完成。

## 二次剩余：Cipolla 模平方根

代码：[mod_sqrt.cpp](mod_sqrt.cpp)，单函数，仅依赖缺省源中的 i64、fi、se 和标准库。不需要原根、因数分解、逆元或外置模幂；用 `pair<i64,i64>` 表示扩域元素，不增加扩域结构体或二元数别名。

选择 Cipolla 的理由是：找到一个非剩余后，主流程就是一次二元数模幂；在理想随机模型下只需 O(log p) 次固定宽度运算，适合对照资料手写。另为 `p%4==3` 保留短的直接公式，减少这类模数的工作。算法依据可参见 [Handbook of Applied Cryptography，第 3.5 节算法 3.36、3.39](https://cacr.uwaterloo.ca/hac/about/chap3.pdf)；书中采用位复杂度，本目录下文采用固定宽度整数运算模型。

```cpp
i64 r = mod_sqrt(n, p); // x^2 ≡ n (mod p) 的最小非负解，无解返回 -1。
```

### 接口、前提与取舍

- `i64 mod_sqrt(i64 n, i64 p)`：n 为任意 i64，包括 `LLONG_MIN`；p 必须为质数，`2<=p<=2^63-1`。本版明确支持完整正有符号 i64 模数，不只限于 10^18 或 2^62−1。
- 不检查 p 的素性；合数、素数幂 p^k（k>1）、p<=1 不属于此接口。`-1` 只表示合法质数模数下无平方根，不是非法模数的检测结果。处理一般合数的分解、提升和 CRT 组合尚未提供。
- 入口先把 n 归一化到 `[0,p)`；归一化后为 0 时返回 0，不要求 n 可逆。p=2 时返回 n 的奇偶余数，只有一个根；没有奇素数的前提漏洞。
- 奇素数下非零剩余恰有两个根 r、p−r，返回其中较小者，范围为 `[1,p/2]`。只有返回值不为 -1 且 p 为奇数、r 非零时，另一个不同的根才是 p−r。零与模 2 的根只有一个，不应重复输出。
- 不修改调用者输入、不保存输入引用；每次返回标量，可连续调用。每次进入 Cipolla 分支时构造局部 `mt19937_64 rnd(3663)`，不使用 static，也不保留跨调用状态。同一组参数每次从相同候选序列开始，调用顺序不改变其候选序列和最小根。
- 不提供外部预处理、批量建表、缓存或种子参数；需要更换固定种子可修改该行。没有容量参数、按输入规模分配的数组或递归栈；pair 的两项依次为实部和 sqrt(w) 的系数。

### 正确性要点

先独立处理 p=2 与 n=0。对奇素数、非零 n，用 Euler 判据计算 `n^((p-1)/2)`：不等于 1 则无解。代码中的 p/2 等于这个指数。若 `p%4==3`，`n^((p+1)/4)` 的平方为 n，直接归一到两个根中的较小者即可。

其余情形随机选 a，使 `w=a^2-n` 为二次非剩余。需要严格满足 `w^((p-1)/2)=p-1`，w=0 不能接受，必须重试。在二次扩域中用 `(u,v)` 表示 `u+v*s`，其中 `s^2=w`，乘法为 `(u*x+v*y*w, u*y+v*x)`，各项按 p 取模。

由于 w 是非剩余，扩域为域且 `s^p=-s`，从而 `(a+s)^(p+1)=(a+s)(a-s)=n`。所以 `r=(a+s)^((p+1)/2)` 满足 r^2=n。n 已知为非零平方，方程在原域中已有两个根，而域中的二次多项式至多有两个根，故所得 r 也在原域，虚部为 0。最后取 `min(r,p-r)`，结果不依赖随机选到哪一个 a。

### 完整 i64 的溢出检查

- 归一化使用 `%p` 后修正负余数，p 正且不为 -1，因此 `LLONG_MIN` 也安全；负余数加 p 的结果在 `[0,p)`，不溢出。
- 标量模乘和 a*a 先扩展到 i128；`a*a-n+p` 整体在 i128 中计算，不先缩回 i64 再加 p。a、n 已归一化，取模后的 w 位于 `[0,p)`。
- 扩域实部含三个因子 v*y*w，不能仅在最前面转换为 i128 就直接连乘：三个 i64 因子的乘积可能超过 i128。代码先算 `t=v*y%p`，再算 t*w。
- 扩域两项相加时始终在 i128 中：每个被加乘积最多为 `(p-1)^2`，两项和不超过 `2*(2^63-2)^2 < 2^127-1`，因此有符号 i128 足够。虚部的两个乘积和也满足同一界限。取模后再安全缩回 i64。
- 对奇素数分别用 `p/2+1`、`p/4+1` 表示 `(p+1)/2`、`(p+1)/4`，不先在 i64 中计算 p+1。返回前 p−r 也在 i64 范围内。

### 随机性与复杂度

设实际尝试了 T 个 a，每次直接使用一个引擎输出。归一化、常数分支之外，每次 Euler 检验、非剩余检查和最终扩域模幂各为 O(log p) 次固定宽度运算，总工作为 `O((T+1)*log p)`。p=2 或归一化 n=0 为 O(1)，无根输入和 `p%4==3` 的路径为 O(log p)。不把源码中可能多次执行的随机循环当作最坏常数时间。

为减少手写代码，使用 `a=i64(rnd()%p)`，允许取模偏差。结果位于 `[0,p)`，缩回 i64 安全。在理想模型中，设原始 64 位输出独立均匀，`N=2^64`、`k=floor(N/p)>=2`，每个余数有 k 或 k+1 个原像。实际 Cipolla 分支中 p>=5，且有 `(p-1)/2` 个成功的 a，因此成功概率至少为 `k*(p-1)/(2N)`。由 `N<(k+1)*p`，成功概率大于 `(p-1)/(3p)>=4/15>1/4`，所以期望尝试次数不超过 4，取模偏差不改变期望 O(log p) 的阶。

实际代码使用固定种子的有限状态伪随机引擎，不能据此承诺每个输入、每种状态都有有限的最坏重试次数，或给这个固定序列套用无条件的严格随机期望。随机性只影响耗时；在满足素数前提时，返回值的正确性由代数判据保证。

空间 O(1)，包含固定大小的 mt19937_64 状态、固定数量的 pair 与模幂局部变量；每次进入随机分支都重新初始化固定大小的引擎，这项开销已计入常数工作。不使用 static，不将重复查询当作重新播种的独立随机实验。没有按 p 建表或排序，也不包含输入规模相关的分配。

## 类欧几里得：专用 floor_sum

第一项求和独立提供两份短实现，不经过万欧状态。沿用参数顺序 `(n,a,b,c)` 与闭区间 `[0,n]`，求 `F=sum floor((a*i+b)/c)`。这与 [ACL floor_sum](https://atcoder.github.io/ac-library/production/document_en/math.html) 的 `(n,m,a,b)`、`[0,n)` 接口不同，不能直接照搬其调用顺序。

| 文件与接口 | 返回内容 | 依赖 |
| --- | --- | --- |
| [floor_sum.cpp](floor_sum.cpp)：`i64 floor_sum(i64 n,i64 a,i64 b,i64 c)` | 不取模的精确 F，要求答案装入 i64 | 仅缺省源 i64；i128 只用于内部中间运算 |
| [floor_sum_mod.cpp](floor_sum_mod.cpp)：`int floor_sum_mod(i64 n,i64 a,i64 b,i64 c)` | F mod 998244353，位于 `[0,998244353)` | 缺省源 i64；模数与 inv2 内置 |

两函数名字不同，可同时粘贴，不相互依赖。没有另写求平方和、加权和的专用类欧递推，这些交给后面的万欧。

### 前提与边界

- `0<=a,b,n<=2^62-1`，`1<=c<=2^62-1`。任意负 n 表示空区间并返回 0；a、b 不支持负数。c 为普通正整数分母，不必为质数，也不要求 c 在答案模数下可逆。包含 c=998244353 或其倍数。
- 不取模版另要求精确答案 `F<=2^63-1`，不提供溢出检测。i64 输入本身不能保证答案装进 i64：例如 n、a 接近 2^62 且 c=1 时，F 的量级可达 n^2*a。超过该前提不能靠窄化转换或取模掩盖。
- 固定模数版没有精确答案装入 i64 或 i128 的要求，只在计算几何边界时使用 i128，累加的答案始终按模数处理。
- n=0 返回 floor(b/c)，不是空区间；a=0 返回 `(n+1)*floor(b/c)` 的精确值或对应模数值。c=1、a>=c、b>=c 均支持，入口不需要自行约分。
- 两者参数按值传递，不修改输入、不保留引用或持久状态，可重复调用。没有数组、容量、构建或追加接口。精确返回值为 i64，可直接用 ostream 输出。

### 计算与安全性

将内部 n 改为项数 N=n+1。每轮先拆出整商，对答案加上 `N*(N-1)/2*(a/c)+N*(b/c)`，再令 a、b 对 c 取余。随后设 `y=a*N+b`：若 y<c，剩余为 0；否则把状态更新为 `(N,a,b,c)=(floor(y/c),c,y%c,a)`。这是格点交换后的同一 floor_sum，不需要像原递归写法那样做 n*m 与递归答案的相减，也不再构造只使用第一项的 array。

归一化后 a<c、b<c，因此 `floor(y/c)<=N`；内部项数从不超过初始的 2^62，缩回 i64 安全。只有 y>=c 时才交换分母，此时 a 不可能为 0，故新分母保持正数。几何乘加 `a*N+b` 先用 i128，最大量级小于 2^124。

精确版先算 `i128(N)*(N-1)/2`，即使后面的整商为 0，也不能先用 i64 算可能很大的三角数。单轮新增贡献是最终 F 的非负分拆之一，因此在 F 能装入 i64 的前提下，新增贡献可以安全缩回 i64，之后的累加也安全。固定模数版先缩小 N 和整商，再使用内置的 2 的逆元；两个新贡献与旧答案之和小于 `2*mod^2+mod`，i64 足够。

每轮分母按欧几里得余数递减，固定宽度运算模型下最坏时间 `O(1+log(c+1))`，空间 O(1)，无递归、初始化表或排序。这里 c 是整数分母，998244353 才是固定答案模数。

原先第一段 calc 只实现 F，返回数组的后两项没有计算。例如 `(n,a,b,c)=(1,1,0,1)` 时返回 `{1,0,0}`，完整三项应为 `{1,1,1}`；这是未完成后两项，不能据此认为第一项的类欧递推有误。

## 万能欧几里得：有序路径拼接

代码：[euclid.cpp](euclid.cpp)，仅依赖 i64 和标准库，包含幺半群重复拼接 `monoid_pow` 与通用 `euclid`。保留原代码的整商展开、交换 U/R、递归处理中段的结构，几何乘加改用 i128。

```cpp
template<class T> T monoid_pow(T x, i64 k);
template<class T> T euclid(i64 p,i64 q,i64 r,i64 l,T U,T R);
```

### 路径与状态契约

- `0<=p,l<=2^62-1`、`1<=q<=2^62-1`、`0<=r<q`。l 为横向 R 的个数；没有答案模数参数。所有除法都是几何整数除法，不涉及模逆元，不要求互质。
- 令 `h_i=floor((p*i+r)/q)`，h_0=0，返回依次拼接 `U^(h_i-h_(i-1)) R`，i 从 1 到 l。竖向 U 总数为 h_l，所有 U 在对应 R 之前，顺序不能颠倒。
- r 必须已归一化。若真实起始常数为 b，先拼接 `U^(b/q)`，再传入 r=b%q。通用函数本身不加入原点 R，也不计初始高度的 U。
- l=0 返回 `T{}`；p=0 返回 R 的 l 次拼接，不会除以 0。`monoid_pow` 的 k 要求非负 i64，k=0 返回单位元；重复拼接不要求交换律。
- T 必须默认构造成拼接单位元，`operator+` 必须结合且表示从左到右拼接、返回新的值。可以是矩阵乘积或路径统计，不能默认把全零矩阵当作乘法单位元。T 的构造、拷贝、赋值和内部算术须支持这些操作，几何参数安全不代表用户状态也自动不会溢出。
- 参数与状态按值传递，不修改调用者、不保留输入引用，可重复调用。没有持久状态、缓存、数组容量或建图接口。路径只压缩计算，不显式生成可能长于 i64 的完整 U/R 序列；结果能否表示由 T 自身负责。

### 递推与复杂度

p>=q 时，每个横步前固定增加 floor(p/q) 个 U，所以将 R 替换成 `U^(p/q)+R`，然后 p%=q。否则令 `m=floor((p*l+r)/q)`；m=0 时全是 R。m>0 时，前段横步数为 `head=floor((q-r-1)/p)`，中段交换 U、R 并交换斜率，剩余末段为 `tail=l-floor((q*m-r-1)/p)`。

只有 m>0 才除以 p，此时 p>0；`0<=m<=l`，新长度 m−1 非负且严格小于 l。新余数 `(q-r-1)%p` 处于新分母范围。`q*m-r-1` 非负且小于 p*l，所以 tail 在 `[1,l]`。p*l+r、q*m−r−1 均先扩展到 i128，输入上界下小于 2^124，除后缩回 i64 有界。

不能仅因递归层中调用二进制幂就机械写成 log^2。一次翻转中 head<=floor(q/p)、tail<=ceil(q/p)，它们的重复拼接成本由下一步欧几里得商控制。各步的 `log(商+1)` 之和为 O(log(p+q+1))；终止处的重复拼接另需 O(log(l+1))。因此最坏拼接次数为 `O(log(p+q+1)+log(l+1))`。`monoid_pow` 在右移指数后再判断是否需要平方，省去每次重复拼接中最后一次无用的状态翻倍。

若 T 的拼接、构造和拷贝均为 O(1)，总时间与上述次数同阶；若 T 是实际字符串等可变长对象，必须另计其运算和复制成本，不能据此宣称整个字符串输出也是对数时间。递归栈为 `O(1+log(min(p,q)+1))` 个定长状态帧，固定尺寸 T 时相应空间为 O(log(min(p,q)+2))；T 自身的动态存储另计。二进制幂是迭代实现，不增加递归栈。

## 万欧实例：三项 floor 统计

代码：[floor_moments.cpp](floor_moments.cpp)，先粘贴 euclid.cpp。状态组织为 `struct FloorMoments`，最终入口按约定命名为 `solve`。

`array<int,3> FloorMoments::solve(i64 n,i64 a,i64 b,i64 c)` 返回 `{F,G,H}`：

- `F=sum floor((a*i+b)/c)`；
- `G=sum floor((a*i+b)/c)^2`；
- `H=sum i*floor((a*i+b)/c)`。

三者均为闭区间 i=0..n，固定模数 998244353，返回值在 `[0,mod)`。参数范围与专用 floor_sum 相同，但不要求精确 F、G、H 装入 i64 或 i128；负 n 返回全零。n=0 时分别为 `{b/c,(b/c)^2,0}` 的模数值。输入不修改、无引用或持久状态，支持重复调用。

### 五项状态与拼接

r、u 分别为横步 R、竖步 U 的个数；sum 为每个 R 处竖向高度的和，sq 为高度平方和，mix 为该 R 的横向下标乘高度之和。所有字段按 mod 取余，存 int，模乘中间值用 i64。

相较原 node，把 R 的下标改成从 0 开始，并删去冗余的 sumr：一个片段里 R 的局部下标必是 0..r−1，和直接由 r*(r−1)/2 得到。拼接 B 到 A 后，B 的横坐标整体加 A.r，高度整体加 A.u，因此：

- sum 增加 B.sum+A.u*B.r；
- sq 增加 B.sq+2*A.u*B.sum+A.u^2*B.r；
- mix 增加 B.mix+A.r*B.sum+A.u*B.r*A.r+A.u*B.r*(B.r−1)/2。

这里的三角数由剩余计数计算仍正确，因为 mod 为奇数，`r*(r-1)/2` 作为整数函数的值按 mod 具有周期 mod；换成偶数答案模数不能直接沿用这一处理。字段初值应为单位元全零，或由 U={0,1}、R={1} 及拼接得到，不要传入未归一化的手工字段值。

实际拼接整条路径为 `U^(b/c)+R+euclid(a,c,b%c,n,U,R)`：初始纯 U 段直接构造成 `{0,int((b/c)%mod)}`，省掉这一次二进制幂；第一个 R 就是 i=0 的原点，后续 R 自然对应 1..n。三项可直接返回，省去原程序最后对 b/c 和 (b/c)^2 的额外补算。

所有字段都小于 mod；两个 int 字段相加小于 INT_MAX。平方和与混合项中至多出现三个约为 mod^2 的 i64 乘积，链式三因子先按 mod 缩小，表达式总量小于 `3*mod^2+2*mod < 2^63-1`，不需要状态合并中的 i128。几何递推仍使用 i128。每次状态拼接 O(1)，求解最坏时间 `O(log(a+c+1)+log(n+1))`，递归栈 O(log(min(a,c)+2))，包含各层状态副本；无筛表、排序或输出数组，返回结果为常数大小。

## 常数优化参考：倒数乘法除法

代码：[qdiv.cpp](qdiv.cpp)。保留提供的向上取整倒数表与乘法取高位写法，仅作为参考，后续模板代码均使用普通整数除法，不使用本优化。放进 `QDiv` 命名空间以避免倒数数组与全局求逆元函数 `inv` 重名；局部使用 `u64=unsigned long long`、`u128=unsigned __int128`，不改变缺省源中有符号 `i64` 的含义。

```cpp
QDiv::init();

```

### 接口、范围与状态

- `void QDiv::init()` 预处理 `[1,B)` 的倒数，`B` 是可按需调整的容量常数，代码以 `100000` 为例；要求 `3<=B<=INT_MAX` 且数组能分配。`inv` 不是模逆元，不要求 y 为质数，也没有模可逆性条件。
- `u64 QDiv::qdiv(u128 x,u64 y)` 计算非负整数的向下取整商。先调用 `init()`；要求 `2<=y<B`，并满足下述精确性范围。范围随实际除数或所选 B 确定，不绑定某个特定容量下的误差上界；不保证整个有符号 i64 范围或任意 u128 被除数都精确。
- 更一般地，对 `0<=x<2^64`，**`x*(y-1)<2^64` 是充分条件**，乘积按数学整数理解，若在程序中检查须使用 u128。若需对全部表内除数统一保证，可取 **`x*(B-2)<2^64`**，等价于 `x<=floor((2^64-1)/(B-2))`；修改 B 后直接按新容量计算。该充分条件不满足时不代表一定错误，可用下一节的充要条件判断。
- `y=1` 不支持：原公式的倒数为 2^64，存入 u64 后回绕成 0。调用者遇到 1 应直接取 x，不调用本函数；这里保留原短写法，没有增加查询分支。`y=0` 是非法除数，`y>=B` 会越界，均不得调用。负数也不支持，隐式转成无符号数不会得到有符号除法语义。
- `u128` 形参保留原接口，用于使乘法先扩展，并不表示支持任意 128 位输入。只要 x 是 u64 范围且 y 合法，`x*inv[y]` 一定小于 2^128，乘法不会回绕；在更宽范围内，即使数学商能用 u64 表示，乘法也可能回绕。
- 表具有静态存储期，无自动初始化计算；首次使用前必须显式 `init()`，否则零表不能计算有效商。可重复初始化，查询不改表或输入、不保存输入引用。调用者不应修改表；本接口没有追加或修改倒数的功能。

### 正确性与误差

记 `M=2^64`、`v=ceil(M/y)`、`e=y*v-M`。当 `2<=y<B` 时，表项恰为 v，且 `0<=e<y`。令 `x=q*y+r`、`0<=r<y`，在乘积不回绕且商可返回的前提下：

```text
qdiv(x,y) = q + floor((r*M + x*e)/(y*M))
正确当且仅当 x*e < (y-r)*M。
```

这解释了为什么“乘法不溢出”仍不足以保证精确。对 u64 范围的 x，误差项小于 2，因此结果只可能正确或偏大 1，不会偏小；原片段没有执行误差修正。由 `e<=y-1` 及 `y-r>=1` 可直接得到上一节的通用充分条件。尤其 y 为不小于 2 的二次幂时 e=0，整个 u64 范围都精确。

向上取整倒数的误差推导亦可参考 Ertl 的原论文 [Integer Division by Multiplying with the Double-Width Reciprocal，§2](https://www.complang.tuwien.ac.at/papers/ertl19kps.pdf)。这里保存的是原片段的单字倒数，不是该文后续的双字倒数实现；当前表的具体范围和反例按本节推导。

## 杜教筛：以 φ 前缀和为例

代码：[dujiao.cpp](dujiao.cpp)。杜教筛是通过狄利克雷卷积递推前缀和的方法，并不限于 φ 或 μ。这里只保留 **φ 的一份实现**，包括线性预筛、平方根拆分递推和记忆化；不写额外的通用函数封装。使用普通整数除法和标准库 unordered_map，不依赖其他数论模板。

```cpp
Dujiao d; // 默认预筛到 1000000，各询问共用缓存
cout << d.solve(n) << '\n'; // i64，sum_{i=1}^n phi(i)
```

### 一般计算原理

设算术函数 `h=f*g`，其中 * 是狄利克雷卷积；记 f、g、h 的前缀和分别为 F、G、H。交换求和顺序，有：

```text
H(n) = sum_{i=1}^n g(i)*F(floor(n/i))
g(1)*F(n) = H(n) - sum_{i=2}^n g(i)*F(floor(n/i))
```

因此，选择一个辅助函数 g，使 G、H 容易计算，预筛小范围的 F，再按整除商递推并记忆化即可。普通整除分块时，一块 `[l,r]` 的系数为 `G(r)-G(l-1)`。这不要求 f、g 必须是积性函数；但要求能高效取得所需函数值与前缀和，不能对任意函数直接承诺相同复杂度。整数计算时须有 g(1) 非零，恢复 F(n) 的除法必须精确；模意义下则要求 g(1) 可逆。

本实现保留原代码的平方根拆分。令 `s=floor(sqrt(n))`，双曲线区域 i*j<=n 中至少一个坐标不超过 s；两侧分别求和，扣除重复计算的正方形：

```text
H(n) = sum_{i=1}^s [f(i)*G(floor(n/i)) + g(i)*F(floor(n/i))] - F(s)*G(s)
g(1)*F(n) = H(n) - f(1)*G(n)
            - sum_{i=2}^s [f(i)*G(floor(n/i)) + g(i)*F(floor(n/i))] + F(s)*G(s)
```

对代码中的例子，取 `f=φ、g=1、h=id`，则 `f(1)=g(1)=1、G(n)=n、H(n)=n(n+1)/2`，所以：

```text
F(n) = n(n+1)/2 - n - sum_{i=2}^s [F(floor(n/i)) + phi(i)*floor(n/i)] + s*F(s)
```

这对应循环中的两项减法及最后的 `s*solve(s)-n`。改为其他函数时，须相应修改预筛、H 和卷积权重；本片段没有自动支持其他函数的接口。

### 接口、边界与重用

- `Dujiao(int m=1000000)` 预筛闭区间 `[1,m]`，m 是最大预筛下标，两个数组的长度均为 m+1。要求 `1<=m<INT_MAX` 且内存足够。用 `phi[i]==0` 判断未筛到的数，临时质数数组在构造结束后释放。
- **`i64 solve(int n)` 仅返回 φ 前缀和**。支持 `0<=n<=INT_MAX`，并须满足 **`floor(sqrt(n))<=m`**：此平方根拆分会直接读取 `phi[i]`，不能无条件将预筛上界缩到 1。查询上界等价于 `n<=(m+1)^2-1`，还须受 INT_MAX 限制。默认 m=1000000 足够覆盖全部 int 查询，最小取 m=46340 也能覆盖全部 int 查询。
- `solve(0)=0、solve(1)=1`，约定 φ(1)=1；负数输入不支持。不取模，不要求模数或逆元，也不扩展到 i64 查询。
- 对象自有数组和缓存，不保存输入引用；可按任意顺序重复查询。大于 m 的前缀和会缓存，查询不改函数值数组。调用者不要修改内部数据；未提供原地重筛或修改函数值接口，需要改变预筛上界时重新构造对象。

### 算术范围与复杂度

φ 单点用 int；前缀、返回值及递推中间值用 i64。线性筛先检查 `p>m/i` 再算 `i*p`，保证下标及 φ 转移乘法不超过 m。`n+1` 在扩展到 i64 后计算，避免 INT_MAX 先加一溢出。循环检查 `i64(s)*s<=n`，退出后 s 减一，得到精确整数平方根。

`F(n)<=n(n+1)/2<2^61`；平方根补回项 `s*F(s)<=s^2*(s+1)/2<5*10^13`。循环只减非负量，部分和及恢复操作均在 i64 范围内，所有可能超出 int 的乘法均先扩展。

构造及数组清零为 `O(m)`。一次未缓存的 n>m，设 `K=floor(n/(m+1))`，新增状态至多 K 个，均属于 floor(n/k)。各状态 v 的循环量为 O(sqrt(v))，总量不超过 `sum_{k<=K} O(sqrt(n/k))=O(n/sqrt(m))`。在哈希单次操作均摊期望 O(1) 的假设下，冷查询为 `O(n/sqrt(m))`，含构造为 `O(m+n/sqrt(m))`；并非 O(sqrt(n))。默认整数哈希未随机化，不给对抗输入下的同阶最坏保证。均衡预筛规模通常约为 n^(2/3)，也须满足平方根前提和内存限制。

预筛内查询 O(1)，缓存命中为期望 O(1)。两个数组占 `12*(m+1)` 字节，不含 vector 对象和哈希节点。计入构造时临时质数数组、缓存和 O(log(n+1)) 递归栈，空间为 `O(m+K+log(n+1))`，返回值 O(1)。多组数据共用预处理，缓存按状态并集增长，不能只按最大 n 的 K 估算混合询问后的全部缓存。

原题 [洛谷 P4213](https://www.luogu.com.cn/problem/P4213) 给出 `T<=10、1<=n<2^31`；当前示例沿用该查询范围，只计算 φ 前缀，不再提供该题要求的 μ 输出。未提交在线评测。


### 接口与适用范围

- **`int Min25::solve(i64 n)`** 返回闭区间 `[1,n]` 上 F 的和，模数固定 `1000000007`，结果归一化到 `[0,mod)`。支持 **`0<=n<=10^10`**，`solve(0)=0、solve(1)=1`。这沿用 [P5325](https://www.luogu.com.cn/problem/P5325) 的正输入范围，并补充空前缀；不是对完整 i64 值域的容量或效率保证。负数输入不支持，没有无解标记。
- F 是积性函数，即互质乘积上相乘，**不要求完全积性**。通常的推广条件是：质数处 F(p) 能拆成少量可筛的完全积性函数（本例为 p²−p），且 F(p^e) 能快速计算。低次多项式是常见情形；质数幂处的值不必等于 F(p)^e，也不能仅凭 F(p) 推出。当前代码只实现这一例子，更换函数须同时修改质数基底、幂和初值、质数贡献与质数幂贡献。
- 当前模数为质数，2、6 均可逆，`166666668` 是 6 的逆元；S1 使用乘积先整除 2，S2 使用逆元。没有对输入 n 或质数 p 求模逆元。换模数时必须重新检查分母可逆性与所有中间值范围，不能只替换 mod。
- 每次 solve 均清空质数表并重建两张表，可复用同一对象，支持大小交错、0、1 和重复输入。没有跨询问缓存、增量追加或修改目标函数的接口；不保存输入引用。vector 的容量可能保留，反复构建后的常驻容量应按曾处理的最大 n 估算，而非只看最后一次 n。
- 其余成员是当前构建的辅助接口，调用者不要修改状态。`id(x)`、`calc(x,i)` 的 x 只能是当前 n 的**不同正整除商**，不支持任意 x；`val(i)` 的下标为 `[1,m]`。`calc` 返回内部有符号余数，不包含 F(1)，对外只使用 solve。

### 第一阶段：筛质数的一次、二次幂和

令 `s=floor(sqrt(n))`、`m=s+floor(n/(s+1))`。不同正整除商依次递增编号：前 s 项为 1..s，后面为 `n/(m+1-i)`；总数 m 为 O(sqrt(n))。`id` 与 `val` 可互相转换，不需要额外映射数组。递归中 `floor(floor(n/a)/b)=floor(n/(a*b))`，因此仍然落在同一套编号中。

对于 k=1、2，先以 `sum_{t=2}^x t^k` 初始化表 H_k(x)，再按递增质数 p 更新所有 x>=p²：

```text
H_k(x) -= p^k * [H_k(floor(x/p)) - H_k(p-1)]
```

扣除的是最小质因子恰为 p 的合数权值。完全积性的单项式满足 `(p*t)^k=p^k*t^k`，所以可提出 p^k；减掉 H_k(p−1) 是排除已经保留的小质数。对固定 p 必须按 **x 递减** 更新，以便读到上一个筛阶段的 H_k(x/p)。最终 `f[id(x)]=sum_{p<=x}p`、`g[id(x)]=sum_{p<=x}p²`，两表相减就是质数上的 F 之和。

这里将原代码从 1 开始的幂和显式减去 1，使表直接不包含整数 1。原写法在差分和 g−f 中也会抵消这个常数；这一调整只让表意更直接，不改变结果。

### 第二阶段：按最小质因子枚举

`calc(x,i)` 表示 `2<=t<=x`、t 不含前 i 个质数作为因子时的 F 之和，i 在 `[0,size(pr)]`。先取全部质数贡献 `g[id(x)]-f[id(x)]`，再减去前 i 个质数的贡献。剩下的合数唯一写成 `p^e*t`，其中 p 是最小质因子，t=1 或 t 的质因子都大于 p：

```text
calc(x,i) = 质数贡献
  + sum_{k>=i, p=pr[k], p²<=x}
      sum_{e>=1, p^(e+1)<=x}
        [F(p^e)*calc(floor(x/p^e),k+1) + F(p^(e+1))]
```

第一项计算含更大质因子的合数，第二项补入纯质数幂 p²、p³……，一次质数已在最初的质数贡献里，不再重复。最后 solve 加入 F(1)。这与原代码的 `F(p^e)*(calc(...)+(e>1))` 按幂次重排等价；内层条件改为 `pw<=x/p`，既减少末尾必为零的递归，也保证 `pw*p<=x`，循环更新不会溢出。

只预筛到 s，不再多筛 199 个数。i 等于质数表长度时不能直接判零：x 可能仍包含大于 s 的质数，它们由质数和表给出。代码仅以 `x<=1` 或 `i>0 且 x<=pr[i-1]` 判空，既不访问 pr 的尾后元素，也保留这些大质数贡献。

### 算术与容量

n、x、质数幂及乘法中间值用 i64；编号、质数和模余数用 int。先以浮点估计平方根，再用整数平方比较校正。n<=10^10 时，s<=100000、m<=199999，f、g 各需至多 200000 个 int；预筛标记为 s+1 个 int，质数表有 π(s) 项，没有固定全局容量。

`i64(p)*p` 避免 int 平方溢出；质数幂每次乘法前均已由 `pw<=x/p` 保证结果不超过 x。计算 F(p^e) 时先对 p^e 取模，不会计算可能超过 i64 的完整平方。内部 f、g、calc 允许负余数；各值绝对值小于 mod，表差小于 2mod，仍在 int 内。初始化 S2 以及递归两项相加的 i64 中间量均小于约 `2*mod²+4*mod<2^63`，不需要 i128。最终在 int 内加一次 mod 并取余也安全，因为 2mod<INT_MAX。

### 分阶段复杂度

埃氏预筛 `O(s*log log(s+2))`，表的分配与初值 `O(s)`。质数和筛选更新次数为：

```text
sum_{p<=s} #{x 是 n 的不同整除商 : x>=p²}
  = O(n^(3/4)/log(n+2))。
```

把 p 按 n^(1/4) 分界：小 p 至多更新 O(sqrt(n)) 项，大 p 更新 O(n/p²) 项，再按质数分布估计即可。两列是固定常数，普通除法按固定宽度 O(1) 计。

**上述界只针对第一阶段，不能直接移给这份没有记忆化的恢复递归。** 对第二阶段，令 `R(n)=#{d>=2 : d*Pmax(d)<=n}`，其中 Pmax(d) 是最大质因子。一次递归调用由路径上已取质数幂的乘积 d 标识，质数严格递增，d 的分解唯一；内层条件恰为新 d 仍满足 d*Pmax(d)<=n。n>=1 时调用数恰为 R(n)+1，总调用和循环开销为 `Θ(1+R(n))`，不同路径仍可能重复计算同一个 `(x,i)`。

所以完整时间为 `Θ(n^(3/4)/log(n+2)+R(n))`，预筛项已被前者支配。进一步有 `R(n)=o(n)` 且 `R(n)=n^(1-o(1))`：对任意固定 k，k 个不超过 n^(1/(k+1)) 的不同质数之积都对应一个合法 d，给出 `R(n)=Ω(n^(k/(k+1))/log^k(n))`。故不存在固定 α<1 的 O(n^α) 总时间保证，不能将它整体记作 O(n^(3/4)/log n)。严格证明、反向 DP 递推、实测数据及统计方式见 [Min_25 递归／反向 DP 对照](tests/min25_benchmark.md)。

本实现保留直接递归恢复，没有替换为反向 DP。后者合并各质数阶段的整除商状态，完整时间 O(n^(3/4)/log(n+2))；在当前 n<=10^10 的实测中，递归版全程更快。渐近分析可参考 [AtCoder 官方说明](https://atcoder.jp/contests/abc370/editorial/10906)，具体速度取决于实现和规模，不从单次运行推广。

两张表、质数和临时标记共 `O(sqrt(n))` 空间，另有 O(log(n+1)) 递归栈，返回值 O(1)。不含输入流缓冲；没有输出数组、哈希表或随机性。多次 solve 都重新计入构建代价，已经存在的 vector 容量不能省去表重置和计算代价。

## Powerful Number 筛

代码：[pn_sieve.cpp](pn_sieve.cpp)。直接函数，只依赖缺省源中的 i64、vi 和标准库。PN（Powerful Number）指所有质因子指数都不小于 2 的正整数，约定 1 也是 PN。PN 筛通过卷积分解，把积性函数求和转为对这些稀疏整数的枚举。

### 计算原理与适用条件

给定积性函数 F，找另一个积性函数 G，使 `F(1)=G(1)=1`、对每个质数 p 都有 `F(p)=G(p)`，且 G 的前缀和 S_G 容易计算。令 `F=G*H`，* 为狄利克雷卷积，则 H 积性，H(1)=1，并有 H(p)=0。因此 H(d) 只有在 d 是 PN 时才可能非零：

```text
sum_{i<=n} F(i) = sum_{d 是 PN, d<=n} H(d)*S_G(floor(n/d))。
```

质数幂处可用 `H(p^e)=F(p^e)-sum_{j=1}^e G(p^j)*H(p^(e-j))` 求出，不一定有闭式。如果回调求幂值很昂贵，应计入开销或先预处理，不能直接套 O(sqrt(n))。

DFS 按递增质数选取指数 >=2 的质数幂，乘积 d 每种分解恰好产生一次。状态 x=floor(n/d)、v=H(d)，进入节点先累加 v*S_G(x)，然后选取更大的质因子。根节点 d=1 保留 S_G(n) 本身，不能漏掉；幂次从 2 开始，指数 3、5 等同样需要枚举。

每个 PN 都可唯一写成 a²b³，其中 b 无平方因子（不要求 a、b 互质）。数量不超过 `sum_b sqrt(n/b³)=O(sqrt(n))`，同时包含所有平方数，故是 Θ(sqrt(n))。循环每次选中质数至少产生一个子节点，因此不会额外为每个节点扫描整张质数表。

### 接口和范围

`int pn_sieve(i64 n,const vi &pr,int mod,auto h,auto sum_g)`：

- 返回 `[1,n]` 上 F 的和模 mod，归一化到 `[0,mod)`。支持 `0<=n<=2^62-1`、`1<=mod<=INT_MAX`；mod 可合数，也可为 1，本函数没有求逆元。这里给的是整数运算安全范围，不承诺 10^18 规模在比赛时间内可跑完。
- pr 递增且不重复，至少包含全部不超过 floor(sqrt(n)) 的质数，可以包含更多质数。质数值用 int，上述 n 范围保证所需质数不超过 INT_MAX。函数不生成质数表，其构建时间、容量和存储必须另计；缺少质数会漏算，函数不做合法性检测。
- `h(int p,int e,i64 pw)` 返回 H(p^e)，其中 e>=2、pw=p^e；`sum_g(i64 x)` 返回 S_G(x)。两种回调都须返回 `[0,mod)` 内的 int。仅提供取模接口，精确整数求和需另行按值域调整，当前未实现。
- n=0 返回 0，且不调用回调；n=1 返回 S_G(1)。负数和非法模数不支持。不修改 pr，不保存输入引用；回调按值传入，若捕获外部引用，只需保证本次调用期间有效。可重复调用，函数没有持久状态。
- `p*p` 先扩展到 i64；每次 pw 乘 p 前检查 `pw<=x/p`，保证乘积不超过 x。v 与回调结果均小于 INT_MAX，其乘积小于 2^62，累加也在 i64 内；调用者仍须自行保证回调内部的乘法安全。

若两种回调均为 O(1)，枚举时间 Θ(sqrt(n))，额外递归栈 O(log(n+1))，不存储所有 PN。总时间还要加回调的实际开销及外部质数预处理，空间还要加 pr 与回调自有状态，不能只报告枚举部分。

## PN＋杜教筛：P5325 示例

代码：[pn_dujiao.cpp](pn_dujiao.cpp)。先粘贴 pn_sieve.cpp，再粘贴本文件；现有只求 φ 前缀的 dujiao.cpp 不需要粘贴，也没有为本例修改。所有除法均为普通整数除法。

```cpp
PNDujiao s; // 默认预筛到 5000000，适配 n<=1e10 的题目上限
cout << s.solve(n) << '\n';
```

### 本例的分解

目标仍是积性函数 `F(p^e)=p^e*(p^e-1)`。取 `G(n)=n*phi(n)`，便有 F(p)=G(p)=p(p−1)。由局部卷积递推可得：

```text
H(1)=1，H(p)=0，H(p^e)=(e-1)*p^e*(p-1)（e>=2）。
```

例如 H(p²)=p²(p−1)，而 `F(p³)-G(p³)-G(p)*H(p²)=2p³(p−1)`。一般式可直接代入卷积验证，测试还按卷积逐次反求各幂次，独立核对闭式。

G 的前缀和用杜教筛。由 `phi*1=id` 两边乘自变量，得到 `(n*phi)*id=id²`。令 S(x)=sum_{i<=x}i*phi(i)、T1(x)=x(x+1)/2、T2(x)=x(x+1)(2x+1)/6。采用与现有杜教筛相同的平方根两侧拆分，令 s=floor(sqrt(x))：

```text
S(x)=T2(x)-T1(x)
     -sum_{i=2}^s [i*S(floor(x/i)) + i*phi(i)*T1(floor(x/i))]
     +T1(s)*S(s)。
```

预筛小范围的 φ 和 G 前缀，较大的 S(x) 记忆化，最后交给 pn_sieve 枚举并加权。PN 枚举的第一个回调就是 S(n)；当预筛上界 m>=sqrt(n) 时，这次杜教筛已经覆盖所有后续需要的非表内整除商，后面的 PN 回调只需查表或查缓存。

### 接口、容量与状态

- `PNDujiao(int m=5000000)` 预筛闭区间 `[1,m]`，φ、sg 数组长度均为 m+1；pr 保存不超过 m 的全部质数。要求 `1<=m<INT_MAX` 且内存足够。φ 单点用 int，计算 G(i) 时先扩展 i64，再取模。
- **`int solve(i64 n)`** 返回闭区间 `[1,n]` 的 F 和模 `1000000007`；支持 **`0<=n<=10^10`**，且要求 **floor(sqrt(n))<=m**，这一条件同时保证 PN 质数表完整及平方根递推的 φ 下标合法。默认 m 覆盖题目上界；最小取 m=100000 也能覆盖全部查询，但初始化与查询时间取舍不同。
- `solve(0)=0、solve(1)=1`；`sum_g(x)` 是内部的 G 前缀接口，在同样范围内支持 x=0。无负数、无解标记、精确整数返回或可变模数功能。示例模数为质数，初始平方和需要 6 可逆，不能将通用 PN 支持合数模数混同为本例可直接换任意模数。
- 构造一次后可按任意顺序重复查询，共用同一个 G 前缀缓存；缓存键为 i64，因为查询超过 int。用 find 判断缓存命中，数值 0 也是合法缓存结果。缓存值不依赖根 n，因此在不同查询之间仍有效。对象拥有全部数组和缓存、不保存输入引用，没有原地更改函数、模数或预筛上界的接口。
- 数组占 `8*(m+1)` 字节；默认两数组合计 40000008 字节，另计质数 vector 容量与哈希节点。多查询缓存按所有查询状态的并集增长，不只按最后一次 n 估算。

### 算术与复杂度

对 n<=10^10，平方根下标最多 100000；`i64(s)*s` 无浮点误差。T2 先将 n 取模，每步乘法及时取模，最大中间值小于约 2mod²；T1 在 i64 中先整除 2。杜教筛每次减法的两项乘积也在 i64 范围内，最后统一归一化。H 的幂值先取模再乘系数，不计算可能超过 i64 的完整平方。

设预筛上界为 m、单次查询为 n。线性预筛及清零 O(m)，需要 O(m) 空间。按哈希单次操作均摊期望 O(1) 分析，冷查询的加权杜教筛为 O(n/sqrt(m))；PN 枚举 Θ(sqrt(n))，所以含预处理为 **O(m+n/sqrt(m)+sqrt(n))**。取 m 约 n^(2/3) 得 **O(n^(2/3))** 的期望总时间；固定 m 时应使用前一个式子，而非直接宣称 O(n^(2/3))。默认 5000000 是按题目最大输入选择的预筛上界。

单次冷查询缓存状态最多 floor(n/(m+1)) 个，加上 O(log(n+1)) 递归栈，整体空间 O(m+n/m+log(n+1))，不存储 PN 数组或答案数组。默认整数哈希没有随机化，不保证对抗哈希输入下的同阶最坏时间。多个查询共享一次预筛，可复用缓存；每次 PN 枚举仍需重新进行。
